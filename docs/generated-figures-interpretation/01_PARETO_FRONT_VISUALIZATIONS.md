## Overview

The Pareto front represents the set of **non-dominated solutions** where improving one objective (e.g., reducing hard violations) necessarily worsens another objective (e.g., increasing soft penalties). These plots help decision-makers understand the quality-feasibility trade-off space.

---

## 1. `pareto_front.pdf`

### Description
Basic visualization showing the entire final population with the Pareto front highlighted.

### Subplots
**Single Plot**: Final population fitness distribution

### Axes
- **X-axis**: Hard Constraint Violations (count)
  - Represents total number of **must-satisfy** constraint violations
  - Examples: room capacity exceeded, instructor double-booking, course group conflicts
  - **Lower is better** (0 = fully feasible)
  
- **Y-axis**: Soft Constraint Penalty (total penalty score)
  - Represents total penalty from **prefer-satisfy** constraint violations
  - Examples: instructor time preferences, room preferences, minimizing gaps
  - **Lower is better** (0 = all preferences satisfied)

### Visual Elements
- **Blue dots (light)**: All population individuals (typically 100-200 solutions)
- **Red dots (bold, black outline)**: Pareto front solutions (non-dominated)
- **Numbers on dots**: Count of duplicate solutions at that exact location
  - Indicates convergence if many solutions cluster

### Mathematical Interpretation

**Pareto Dominance**: Solution A dominates solution B if:
$$
\begin{align*}
\text{hard}_A &\leq \text{hard}_B \text{ AND} \\
\text{soft}_A &\leq \text{soft}_B \text{ AND} \\
\text{at least one} &\text{ inequality is strict}
\end{align*}
$$

**Pareto Front**: Set of all non-dominated solutions:
$$
\mathcal{P} = \{x \in \text{Population} \mid \nexists y \in \text{Population}: y \succ x\}
$$

### How to Interpret
1. **Ideal point**: Bottom-left corner (0, 0) - rarely achievable
2. **Horizontal spread**: Solutions differ mainly in soft penalties (same hard violations)
3. **Vertical spread**: Solutions differ mainly in hard violations (same soft penalty)
4. **Clustering**: Many overlapping dots indicate convergence to specific solutions
5. **Shape**: 
   - **L-shaped**: Clear trade-off knee point
   - **Linear**: Proportional trade-off across range
   - **Single point**: Only one non-dominated solution found

### Typical Observations
- **Early generations**: Wide scatter, many dominated solutions
- **Late generations**: Tight clustering around Pareto front
- **Good run**: Pareto front contains multiple diverse solutions
- **Poor run**: All solutions have high hard violations (> 10)

## 3. `pareto_front_comprehensive.pdf`

### Description
Four-subplot comprehensive analysis showing population structure and overlaps.

### Subplots

#### Subplot 1 (Top-Left): **All Population Points with Jitter**
- **Purpose**: Reveal overlapping solutions
- **X-axis**: Hard constraint violations (with jitter)
- **Y-axis**: Soft constraint penalty (with jitter)
- **Visual**: Blue dots with slight random displacement
- **Jitter formula**: 
  $$\text{position}_{\text{jittered}} = \text{position}_{\text{actual}} + \mathcal{N}(0, 0.1 \cdot k)$$
  where $k$ is the count of overlapping solutions

**Interpretation**:
- **Tight clusters**: Convergence to specific solutions
- **Scattered**: Population diversity maintained
- **Count in title**: Total individuals (e.g., 200)

#### Subplot 2 (Top-Right): **Population with Pareto Front**
- **Purpose**: Standard Pareto visualization with overlap counts
- **X-axis**: Hard constraint violations
- **Y-axis**: Soft constraint penalty
- **Visual**: 
  - Light blue dots = population
  - Bold red dots = Pareto front
  - Numbers = duplicate count at that location

**Key metric in title**: "X unique solutions" out of total population

**Interpretation**:
- **High unique count** (> 50% of population): Good diversity
- **Low unique count** (< 20% of population): Premature convergence
- **Numbers on dots**: 
  - `1` = single solution (normal)
  - `5+` = strong convergence signal

---

#### Subplot 3 (Bottom-Left): **Population Density with Pareto Front**
- **Purpose**: Show solution concentration via heatmap/contour
- **X-axis**: Hard constraint violations
- **Y-axis**: Soft constraint penalty
- **Visual**: 
  - **Blue gradient/contours**: Kernel density estimation (KDE) or 2D histogram
  - **Small blue dots**: Individual solutions
  - **Bold red dots**: Pareto front
  - **Colorbar**: Density (lighter = more solutions)

**Mathematics**: Uses Gaussian kernel density estimation:
$$
\hat{f}(x) = \frac{1}{n} \sum_{i=1}^{n} K_h(x - x_i)
$$
where $K_h$ is Gaussian kernel with bandwidth $h$.

**Interpretation**:
- **Hot spots** (bright blue): Population converging to these regions
- **Multiple hot spots**: Multi-modal convergence (good diversity)
- **Single hot spot**: Unimodal convergence (risk of local optima)
- **Pareto front on edge of density**: Normal (front is boundary)

**Fallback**: If data has low variance (all solutions nearly identical), falls back to 2D histogram instead of KDE.

---

#### Subplot 4 (Bottom-Right): **Frequency-Coded Population**
- **Purpose**: Size/color encode solution frequency
- **X-axis**: Hard constraint violations
- **Y-axis**: Soft constraint penalty
- **Visual**:
  - **Dots sized by frequency**: Larger = more duplicates
  - **Color scale** (Yellow-Orange-Red): Frequency intensity
  - **Large white-outlined red dots**: Pareto front
  - **Colorbar**: "Point Frequency" (number of duplicates)

**Size formula**: $\text{size} = 25 \times \text{frequency}$

**Interpretation**:
- **Large dots**: Strong convergence to these solutions
- **Small uniform dots**: Good diversity, little convergence
- **Pareto front with large dots**: Algorithm successfully converged to optimal region
- **Pareto front with small dots**: Weak convergence (may need more generations)

## Common Patterns & Diagnostics

### Healthy Convergence
- Pareto front with 5-20 solutions
- Even spacing along front
- Population clustered near front
- Few dominated solutions far from front

### Premature Convergence
- Pareto front with 1-3 solutions
- All population members identical
- Frequency subplot shows 1-2 giant dots
- **Solution**: Increase mutation rate, population size

### Poor Diversity
- Linear Pareto front (no trade-off curve)
- All solutions in narrow region
- **Solution**: Adjust selection pressure, use diversity preservation

### Stagnation
- Pareto front far from ideal point (0, 0)
- High hard violations across all solutions
- **Solution**: Check feasibility, improve repair operators, use local search

### Ideal State
- 10-30 Pareto solutions
- Smooth trade-off curve from low-hard/high-soft to high-hard/low-soft
- Population forming gradient toward front
- Unique solution count > 50% of population size

## Mathematical Background

### Multi-Objective Fitness Function
The schedule engine uses a **two-objective minimization** problem:

$$
\min_{x \in \mathcal{X}} \vec{f}(x) = \begin{pmatrix} f_1(x) \\ f_2(x) \end{pmatrix}
$$

where:
- $f_1(x)$ = total hard constraint violations (integer)
- $f_2(x)$ = total soft constraint penalty (real number)
- $\mathcal{X}$ = set of all possible schedules

### NSGA-II Fitness Assignment
In DEAP, fitness is represented with **weights** $(-1.0, -0.01)$:
```python
fitness.values = (-hard_violations, -soft_penalty)
```

**Negative signs**: Convert minimization to maximization (DEAP convention)
**Weight ratio** $(1.0 : 0.01)$: Hard violations are 100× more important

### Pareto Optimality Conditions
A solution $x^*$ is Pareto optimal if:
$$
\nexists x \in \mathcal{X}: f_i(x) \leq f_i(x^*) \, \forall i \text{ and } f_j(x) < f_j(x^*) \text{ for some } j
$$

**In plain language**: No other solution is better in all objectives simultaneously.
