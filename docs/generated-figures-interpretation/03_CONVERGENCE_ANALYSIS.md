## Overview

Convergence plots show the **temporal evolution** of the algorithm, revealing optimization dynamics, stagnation periods, and improvement rates. These are essential for understanding **how** the algorithm reaches its final state.

## 2. `convergence_multi_metric.pdf`

### Description
Multiple metrics **normalized** to [0, 1] scale and plotted on the same axes for direct comparison.

### Axes
- **X-axis**: Generation
- **Y-axis**: Normalized Metric Value (0 = worst, 1 = best)

### Visual Elements
- **Multiple colored lines**: One per metric
- **Different markers**: Circle, square, triangle, etc.
- **Legend**: Identifies each metric

### Normalization Formula
For each metric history:
$$
\text{normalized}_i = \frac{\text{value}_i - \min(\text{values})}{\max(\text{values}) - \min(\text{values})}
$$

**Note**: Metrics are inverted if needed so higher is always better in plot.

### How to Interpret

#### Synchronized Improvement
- **All lines rising together**: Balanced multi-objective optimization
- **Example**: Hypervolume, spacing, and diversity all improving

#### Conflicting Metrics
- **Some rising, some falling**: Trade-offs occurring
- **Example**: Hypervolume rising (good) while diversity falling (convergence)

#### Dominance
- **One metric flat while others improve**: That metric not limiting factor
- **Example**: Hard violations at 0 (flat) while soft penalties still decreasing

#### Convergence Rates
- **Steep vs. gradual slopes**: Which metrics improve faster
- **Example**: Hard violations drop quickly, soft penalties improve slowly

### Typical Patterns

**Early Generations** (0-100):
- Hard violations: Steep drop
- Feasibility: Steep rise
- Others: Moderate improvement

**Middle Generations** (100-500):
- Hard violations: Stabilized
- Soft penalties: Gradual improvement
- Hypervolume: Steady increase

**Late Generations** (500+):
- All metrics: Plateauing
- Fine-tuning: Small oscillations

## 3. `convergence_rate_hard_violations.pdf`

### Description
Two-panel plot showing **rate of improvement** for hard constraint violations.

### Top Panel: **Hard Violations Evolution**
- **X-axis**: Generation
- **Y-axis**: Hard Violations (count)
- **Visual**: Blue line with fill

Standard convergence plot for context.

### Bottom Panel: **Convergence Rate Analysis**
- **X-axis**: Generation (shifted by window size)
- **Y-axis**: Improvement Rate (Δ violations / generation)
- **Visual**: Bar chart with color-coded bars

### Mathematical Definition

**Convergence rate** with sliding window of size $w = 10$:

$$
\text{rate}_i = \frac{\text{violations}_i - \text{violations}_{i+w}}{w}
$$

**Positive rate**: Improvement (violations decreasing)  
**Negative rate**: Degradation (violations increasing)  
**Zero rate**: Stagnation (no change)

### Color Coding
- **Green bars**: Positive rate (> 0.01) - improving
- **Yellow bars**: Near-zero rate (-0.01 to 0.01) - stagnant
- **Red bars**: Negative rate (< -0.01) - degrading

### How to Interpret

#### Stagnation Detection
**Yellow box** in plot shows:
```
Stagnation: 45.2% of generations
```
This measures what percentage of generations had near-zero improvement.

**Benchmarks**:
- **< 20% stagnation**: Healthy continuous improvement
- **20-40%**: Moderate, acceptable
- **40-60%**: Significant stagnation, may need more generations
- **> 60%**: Severe stagnation, algorithm stuck

#### Rate Patterns

**Fast Convergence**:
- Many tall green bars early
- Short yellow/red bars
- Quick transition to stagnation at optimal

**Slow Convergence**:
- Many moderate green bars throughout
- Gradual decrease in rate
- Extended optimization period

**Unstable**:
- Alternating green and red bars
- Suggests population instability or oscillation

**Stuck**:
- Mostly yellow bars
- Algorithm not finding improvements

### Practical Use

**Early stopping**: If stagnation > 80% for last 100 generations, can stop early

**Tuning**: High stagnation suggests need for:
- Higher mutation rate
- Local search operators
- Larger population
- Different genetic operators

## 4. `hard_constraint_trend.pdf`

### Description
Simple, focused plot of hard constraint violations over generations.

### Axes
- **X-axis**: Generation (0 = initial population)
- **Y-axis**: Hard Violations (count)

### Visual Elements
- **Red line with circular markers**: Violation trend
- **Markers every 15 generations** (approximately)

### How to Interpret

#### Target Trajectory
**Ideal**: Exponential decay to zero
$$
\text{violations}(t) \approx V_0 \cdot e^{-\lambda t}
$$

where $V_0$ is initial violations and $\lambda$ is convergence rate.

#### Failure Modes

**Stuck at constant high value**:
- Problem over-constrained
- Repair operators insufficient
- **Action**: Check input data, improve repair

**Oscillating**:
- Fluctuating up and down
- Population instability
- **Action**: Reduce mutation rate, use elitism

**Slow linear decrease**:
- Inefficient convergence
- **Action**: Increase selection pressure, use local search

```python

```
Useful when violations span orders of magnitude (e.g., 1000 → 1).

## 5. `soft_constraint_trend.pdf`

### Description
Simple, focused plot of soft constraint penalties over generations.

### Axes
- **X-axis**: Generation
- **Y-axis**: Soft Penalty (total penalty score)

### Visual Elements
- **Green line with square markers**: Penalty trend
- **Markers every 15 generations**

### How to Interpret

#### Typical Pattern
1. **Flat or slight increase early**: Algorithm focuses on hard constraints
2. **Decrease after hard plateau**: Algorithm shifts to soft optimization
3. **Logarithmic decay**: Diminishing returns in late generations

#### Two-Phase Optimization

**Phase 1** (hard constraint satisfaction):
$$
\text{Selection priority}: \text{hard violations} \gg \text{soft penalty}
$$

**Phase 2** (soft constraint optimization):
$$
\text{Selection priority}: \text{soft penalty} \text{ (with hard} = 0)
$$

#### Interpreting the Curve

**No improvement**:
- All solutions infeasible (hard > 0)
- Soft constraints conflict with hard
- **Action**: Check constraint compatibility

**Gradual improvement**:
- Normal, healthy optimization
- Soft constraints being satisfied incrementally

**Sudden drops**:
- Breakthrough solutions found
- May indicate constraint structure (e.g., many dependencies)

## 6. `diversity.pdf`

### Description
Population diversity (genetic variation) over generations.

### Axes
- **X-axis**: Generation (0 = initial population)
- **Y-axis**: Average Chromosome Distance (gene differences)

### Visual Elements
- **Orange line with triangle markers**: Diversity trend

### Mathematical Definition

**Average pairwise Hamming distance**:
$$
\text{Diversity} = \frac{2}{n(n-1)} \sum_{i=1}^{n-1} \sum_{j=i+1}^{n} d_H(x_i, x_j)
$$

where:
- $n$ = population size
- $d_H(x_i, x_j)$ = number of differing genes between individuals $i$ and $j$

**For scheduling chromosomes**:
$$
d_H = \sum_{k=1}^{m} \mathbb{1}[\text{gene}_k^{(i)} \neq \text{gene}_k^{(j)}]
$$
where $m$ is chromosome length (number of sessions).

### How to Interpret

#### Healthy Diversity Pattern
1. **High initial value** (~50-80% of max possible)
2. **Gradual decline** (convergence)
3. **Stabilize above zero** (5-20% of max)
4. **Never reaches zero** (maintains variation)

#### Diversity Benchmarks

| Final Diversity | Interpretation | Action |
|----------------|----------------|--------|
| > 30% of max | Excellent diversity | Good |
| 10-30% | Good diversity | Acceptable |
| 5-10% | Minimal diversity | Monitor |
| < 5% | Premature convergence | Increase mutation, diversity preservation |
| ≈ 0% | Complete convergence | Restart with higher diversity |

#### Relationship to Performance

**Exploration vs. Exploitation**:
- **High diversity**: Exploring search space
- **Low diversity**: Exploiting known good regions

**Optimal trade-off**: Gradual decrease from high to moderate

### Premature Convergence

**Warning signs**:
- Diversity drops below 5% before generation 100
- Hypervolume stops improving when diversity crashes
- Population becomes genetically homogeneous

**Causes**:
- Selection pressure too high
- Mutation rate too low
- Population size too small

**Fixes**:
- Increase mutation rate (e.g., 0.05 → 0.10)
- Use diversity preservation (e.g., fitness sharing)
- Increase population size (e.g., 100 → 200)

## Advanced: Convergence Metrics

### Convergence Speed
**Generations to feasibility**:
$$
G_{\text{feas}} = \min\{t \mid \text{hard}(t) = 0\}
$$

**Typical values**:
- Fast: < 100 generations
- Moderate: 100-500 generations
- Slow: > 500 generations

### Improvement Rate
**Average improvement per generation**:
$$
\bar{r} = \frac{\text{metric}_0 - \text{metric}_{\text{final}}}{G_{\text{total}}}
$$

### Stagnation Index
**Percentage of generations with improvement < threshold**:
$$
SI = \frac{|\{t \mid |\text{metric}_{t+1} - \text{metric}_t| < \epsilon\}|}{G_{\text{total}}} \times 100\%
$$

Typical threshold: $\epsilon = 0.01$ for normalized metrics
